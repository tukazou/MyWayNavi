**ナビじゃない、ドライビングパートナー**

## 1. 課題

### 「今のナビは、案内しかしない」

AIに慣れたユーザーからすると、現在のカーナビは著しく気が利かない。

| 不満 | 本質的な問題 |
|---|---|
| 好みのルートを覚えてくれない | コンテキストを学習しない |
| 渋滞時に選択肢を比較してくれない | 情報を解釈して伝えない |
| 目的地の性質を理解しない | 目的を最後まで完遂しない |
| 駐車場入口まで案内しない | 「本当のゴール」を理解しない |

これらの不満に共通するのは、**「情報はあるのに、判断・行動しない」**という点である。

### ターゲットユーザー（ペルソナ）

- SUV・ミニバンなど車幅が大きめの車に乗っている
- AIツールに慣れているエンジニア・IT系ユーザー
- 週末ドライブが多い（近所〜モール、たまに1時間程度）
- 車内で音楽を聴く派
- 道幅が広い・開放感がある道を好む

---

## 2. 解決策

### MyWayNavi

走行履歴・車種・目的地の文脈を理解し、"自分流"のルートを提案するAIナビエージェント。

#### 3つのコアバリュー

**① 走行履歴からの自動学習（設定不要）**
- 何も設定しなくても、走るたびに好みを学習
- 「道幅が広い道が好き」は言葉では説明しにくい → 走行データから推論
- 使えば使うほど、自分色になっていく

**② 渋滞時の状況説明＋選択肢提示**
- 渋滞を検知したら、状況を言葉で説明
- 「渋滞に並ぶ」か「迂回する」かの選択肢を提示
- 最終判断はドライバーに委ねる（押しつけない）

```
「この先の渋滞は、1キロ15分ですが、伸びる可能性があります。
迂回路としては、手前/一つ先の出口で降りる案があります。
到着時間は、渋滞で待ってもあまり変わりません。どうしますか？」
```

**③ 目的地の性質・駐車場まで理解した案内**
- 公園 → 下道優先（ドライブ自体を楽しむ）
- 映画館 → 上映時刻を考慮して高速優先
- 駐車場入口・目的地に近い入口まで案内

## 3. デモシナリオ

**「Movix柏の葉で映画を観に行く」**

1. 利用者：「今日は、Movix柏の葉までのルートを出して」
2. MWN：「映画館ですね。作品の上映時刻は何時ですか？」
3. 利用者：「09:15です」
4. MWN：「上映時刻に間に合うよう、到着時刻が予測しやすい高速ルートを案内します。湾岸習志野ICから乗って、東京外環C3を通り、常磐道柏ICで降りるルートです。まだ時刻が早いので、下道で京葉ICから乗っても到着時刻は10分程度しか違いませんが、高速道路代500円が安くなるルートもあります。どちらで行きますか？」
5. 利用者：「下道で京葉ICまで行くルートは行ったことないから心配だな。いつもの通り湾岸習志野から乗ろう」
6. MWN：「承知しました。では湾岸習志野から乗るルートを、普段走っている道でご案内します」
7. （走行中）MWN：「この先に渋滞があります。渋滞の長さは約1キロ、通り過ぎるまでに15分かかる予測ですが、伸びる可能性があります。迂回路としては、一つ手前の出口で降りる案があります。到着時間は、渋滞で待ってもあまり変わりません。どうしますか？」
8. 利用者：「待ってイライラするのは嫌だな。手前で降りよう」
9. MWN：「承知しました。では1つ手前で降りるルートでご案内します」
10. MWN：「近くまできました。Movix柏の葉は、ららぽーと柏の葉の4階にあります。ご案内する駐車場入り口で駐車場棟の6階、P6まで上がると便利です」
11. 利用者：「おっけー。P6だね」

### このシナリオで実証できること

| ステップ | 実証する価値 |
|---|---|
| 1〜4 | 目的地の性質理解・時刻制約・ルート比較 |
| 5〜6 | 走行履歴から好みのルートを把握 |
| 7〜9 | 渋滞時の状況説明＋選択肢提示 |
| 10〜11 | 本当のゴール（駐車場）まで案内 |

## 5. 技術構成

```
フロントエンド（HTML/CSS/JS）
　↓
バックエンド（Python + FastAPI）
　├── Gemini API（Agent Platform）← 意図理解・返答生成
　├── Google Maps API            ← ルート計算・比較
　└── 走行履歴DB                 ← 好みプロファイル管理
　↓
Cloud Run（デプロイ）
　↑
GitHub Actions（CI/CD）
```

### 「つくる・まわす・とどける」への対応

**つくる**：Gemini APIを中核に、ドライバーの意図を理解し先回りして行動するエージェントを実装

**まわす**：走行データが蓄積されるにつれてパーソナライズ精度が向上。プロンプトの改善はGitHub→CI/CD→Cloud Runで継続的にデプロイ

**とどける**：Cloud Runにデプロイし、動作確認できる状態で提出
